# 통신 프로토콜 (프로토콜 1, 펌웨어 0.2.1)

안경과 수신기(라즈베리파이 등) 사이에 주고받는 패킷 형식이다. 수신 프로그램을 만들 때 이 문서를 기준으로 한다.

근거 코드: `include/sf_core.h`, `src/core/protocol.c`, `src/main.c`, `src/transport.c`. **코드를 바꾸면 이 문서도 같이 고친다.**

## 연결

안경은 USB와 BLE 두 경로로 같은 패킷을 보낸다. USB 연결이 살아 있으면 USB로 보내고, 아니면 BLE로 보낸다.

**USB**

- 보드의 CP2102N(USB-UART)을 통한 시리얼 통신이다. 전송 속도(baud rate)는 보드 정의(`boards/`)에 있다. 아직 저장소에 올라오지 않았다
- USB를 꽂은 뒤 1초가 지나야 쓸 수 있다
- 수신기가 HEARTBEAT를 1.5초 안에 다시 보내지 않으면 안경은 BLE로 돌아간다. **1초 이하 간격으로 HEARTBEAT를 보낸다**

**BLE**

| 항목 | 값 |
|---|---|
| 기기 이름 | `SentiFrame` |
| 서비스 UUID | `0f54f001-e1b4-47d4-bded-55c810ec9020` |
| TX 특성 (안경 → 수신기, Notify) | `0f54f002-e1b4-47d4-bded-55c810ec9020` |
| RX 특성 (수신기 → 안경, Write / Write without response) | `0f54f003-e1b4-47d4-bded-55c810ec9020` |

- **암호화 연결(페어링)이 필수다.** 보안 레벨 2 미만이면 쓰기를 거부한다. 수신기가 TX 알림을 구독하고 암호화까지 끝나야 안경이 보내기 시작한다
- 알림은 **20바이트 조각**으로 나뉘어 온다. 조각을 순서대로 이어 붙이면 USB와 똑같은 바이트 흐름이 된다. 조각 경계와 패킷 경계는 맞지 않는다

## 프레임

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | 2 | 시작 표시 `0xA5 0x5A` |
| 2 | 1 | 프로토콜 버전 = `1` |
| 3 | 1 | 패킷 종류 (아래 표) |
| 4 | 2 | 페이로드 길이 n (최대 96) |
| 6 | 4 | 순번 `seq` — 안경이 패킷을 만들 때마다 1씩 늘어난다 |
| 10 | 4 | 시각 `time_ms` — 안경이 켜진 뒤 경과 ms |
| 14 | 4 | 부팅 ID `boot` — 안경을 켤 때마다 새로 정하는 난수 |
| 18 | n | 페이로드 |
| 18+n | 2 | CRC-16 |

- 모든 정수는 **리틀 엔디언**이다
- CRC는 CRC-16/CCITT-FALSE다(다항식 0x1021, 초깃값 0xFFFF, 반사 없음, 마지막 XOR 없음). 시작 표시부터 페이로드 끝까지 계산한다
- **받는 방법**: `0xA5 0x5A`를 찾고, 버전과 길이를 확인한 뒤 CRC가 맞을 때만 받아들인다. 어긋나면 1바이트를 버리고 다시 찾는다. 펌웨어의 `sf_parser_push`가 같은 방법이다

## 패킷 종류

| 값 | 이름 | 방향 | 확인 응답(ACK) |
|---|---|---|---|
| 1 | HELLO | 양방향 | |
| 2 | HEARTBEAT | 양방향 | |
| 3 | ACK | 수신기 → 안경 | |
| 16 | IMU | 안경 → 수신기 | 없음 |
| 17 | PPG | 안경 → 수신기 | 없음 |
| 18 | STATUS | 안경 → 수신기 (2초마다) | 없음 |
| 19 | EVENT | 안경 → 수신기 | **필요** — 받을 때까지 1초마다 다시 보낸다 |
| 20 | HISTORY | 안경 → 수신기 | **필요** |

## 수신기가 보내는 패킷

`boot`는 안경이 보낸 패킷의 헤더에서 알아낸다. HELLO를 빼면, `boot`가 다른 패킷은 안경이 무시한다.

- **HELLO**: 페이로드 없음, `boot` = 0(처음) 또는 안경의 boot. 안경이 HELLO로 답한다
- **HEARTBEAT**: 페이로드 없음, `boot` = 안경의 boot. **`seq`는 보낼 때마다 늘린다**(USB에서는 늘지 않으면 무시된다). 안경이 HEARTBEAT로 답한다
- **ACK**: 페이로드 4바이트 = 받은 EVENT 또는 HISTORY의 `seq`, `boot` = 안경의 boot

## 안경이 보내는 패킷

### HELLO (6바이트)

| 위치 | 내용 |
|---|---|
| 0 | 프로토콜 버전 (1) |
| 1 | 하드웨어 리비전 (6 = Rev F) |
| 2~4 | 펌웨어 버전 (0, 2, 1) |
| 5 | 켜진 기능 비트: 1 자이로, 2 PPG, 4 배터리 승인, 8 IMU, 16 충전 |

### IMU (14바이트) — 낙상 판정용 원시 데이터

안경은 100Hz로 측정하고, `STREAM_DIVISOR`번째 샘플마다 하나씩 보낸다. 기본값 2이면 50Hz다.

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | 6 | 가속도 X, Y, Z (int16 원시값, **2048 = 1g**, ±16g) |
| 6 | 6 | 자이로 X, Y, Z (int16 원시값, **16.4 = 1°/s**, ±2000°/s). 아래 flags에 "자이로 유효"가 있을 때만 의미가 있다 |
| 12 | 2 | flags: 1 자이로 유효, 2 포화(측정 범위 끝), 4 시각 추정, 8 데이터 끊김 |

- 헤더의 `time_ms`가 샘플 시각이다. 센서 FIFO에서 10ms 간격으로 거꾸로 추정한 값이다
- 재전송이 없다. 빠진 샘플은 `time_ms` 간격으로 알아낸다
- **자이로는 기본 설정에서 꺼져 있다**(전류 절약). 켜려면 `profiles/six_axis.conf`로 빌드한다

### PPG (6바이트)

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | 4 | 측정값 (uint32, 19비트 원시 광신호) |
| 4 | 1 | tag — 센서 FIFO 태그(상위 5비트). 지금 설정은 초록 LED 하나만 쓴다 |
| 5 | 1 | flags: 4 시각 추정(항상), 2 포화, 8 데이터 끊김 |

- 약 50Hz로 측정하고, 100ms마다 모아서 샘플마다 패킷 하나씩 보낸다. 시각은 20ms 간격으로 추정한다
- **심박수(BPM)는 보내지 않는다.** 원시 파형에서 수신기가 계산해야 한다

### STATUS (30바이트, 2초마다)

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | 2 | 배터리 전압 mV (0xFFFF = 측정 실패) |
| 2 | 1 | 전원 종류: 0 없음, 1 알 수 없음, 2 SDP, 3 CDP, 4 DCP, 5 Type-C 1.5A, 6 Type-C 3A |
| 3 | 1 | 상태 비트: 1 충전 켜짐, 2 충전기 고장, 4 IMU 정상, 8 PPG 정상, 16 자이로 사용, 32 배터리 승인, 64 USB 준비, 128 USB 링크 살아 있음 |
| 4, 5 | 1, 1 | 충전기 상태 레지스터 |
| 6 | 1 | 현재 경로: 0 없음, 1 USB, 2 BLE |
| 7 | 1 | ACK를 기다리는 패킷 수 |
| 8 | 4 | 센서 오류 누적 수 |
| 12 | 4 | 보내지 못하고 버린 패킷 수 |
| 16 | 4 | 받다가 버린 바이트 수 |
| 20 | 4 | 이벤트 대기열 넘침 수 |
| 24 | 4 | 기록(HISTORY) 넘침 수 |
| 28 | 2 | STREAM_DIVISOR |

### EVENT (12바이트) — ACK 필요

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | 1 | 종류: **1 충격, 2 낙상 의심**, 3 SOS 버튼, 4 센서 고장 |
| 1 | 1 | 세부: 센서 고장일 때 2 IMU, 3 PPG, 7 충전기 |
| 2 | 2 | flags: 8 = 앞선 기록을 보내는 중이라 이번 기록은 담지 못함 |
| 4 | 2 | 배터리 전압 mV |
| 6 | 2 | 최대 가속도 × 1000 (g) |
| 8 | 2 | 마지막 z × 100 (int16) |
| 10 | 2 | 이 이벤트에 딸린 HISTORY 샘플 수 (충격·SOS일 때) |

- ACK를 받을 때까지 1초마다 다시 보낸다. 대기열은 8개다
- 다시 보낸 패킷을 두 번 받을 수 있다. **같은 (`boot`, `seq`)는 한 번만 처리한다**
- 낙상 판정 규칙은 [README.md](README.md#낙상-판정-알고리즘)에 있다

### HISTORY — ACK 필요

충격이나 SOS 직전 최대 200샘플(100Hz, 2초)을 4샘플씩 나눠 보낸다. 조각마다 ACK를 받아야 다음 조각을 보낸다. 60초 안에 다 보내지 못하면 버린다.

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | 4 | 어느 EVENT의 기록인지 (그 EVENT의 `seq`) |
| 4 | 2 | 전체 샘플 수 |
| 6 | 2 | 이 조각의 시작 위치 |
| 8 | 1 | 이 조각의 샘플 수 n (최대 4) |
| 9 | 18 × n | 샘플마다: `time_ms` uint32, 가속도 int16 × 3, 자이로 int16 × 3, flags uint16 |

- **충격 이전 데이터만 담긴다.** 충격 이후의 움직임이 필요하면 IMU 스트림을 쓴다
